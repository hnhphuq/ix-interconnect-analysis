# IX 互联专线：云厂BGP接入的跨境专线选购，深港/沪港/沪日/沪美套餐与前置机器准备

跨境电商和短视频团队用了几年 IPLC、IEPL 这类传统跨境专线之后，最近两年又冒出一个新名词——IX 互联专线。它没有公网入口，必须借助云厂商的 BGP 网络做前置，延迟比普通公网低、安全属性比传统专线稳，价格又明显便宜。对已经在阿里云、腾讯云、火山引擎、华为云上跑业务的团队来说，IX 已是规划出海网络时绕不开的一类方案。

下面把 IX 互联专线最关键的几件事拆开讲清楚：它到底是怎么连通的、和 IPLC/IEPL 有什么区别、要准备什么样的云前置，以及具体挑选服务商时应该关注哪些套餐和限制。本文会结合 Mkcloud 该系列下的深港、沪港、沪日、沪美四个方向，给出可直接对照选购的产品信息。

## 一、IX 互联专线到底是什么

IX 的全称是 Internet Exchange，也就是互联网交换中心。它本身不是某家机房，而是多家网络在同一物理位置互相交换流量的一套基础设施。

在跨境专线这件事上，所谓的 IX 互联专线，准确说是"通过云厂商 BGP 网络接入、用 IX 作为中转出口的 VPS 专线"。它的几个核心特征是：

- 没有公网入口 IP，只接云厂商的 BGP 内网 IP，普通宽带和普通云主机连不进来；
- 一台 VPS 同时配 1 个独立入口 IP 和 1 个独立出口 IP，业务从入口进、流量从出口出；
- 出口走 IX 交换，再从香港、日本或美国的 BGP 出口节点对外访问；
- 入口这一段必须由用户自己提供符合要求的云前置机。

这套结构的目的很直接：避开公网上的 DDoS 和扫描通报，同时让跨境段保持专线质量。

## 二、IX 互联专线和 IPLC、IEPL 的差异

经常有人把 IPLC、IEPL、IX 混在一起叫"国际专线"，但实际交付方式完全不同：

- IPLC（国际私有租用电路）：端到端的物理层专线，全程专有通道，适合对稳定性极敏感的场景，但价格最高；
- IEPL（国际以太网专线）：基于 MSTP 的端到端以太网专线，带宽调整更灵活，常见于移动出口方向；
- IX 互联专线：入口走云厂商 BGP 内网，跨境段走 IX 交换再到目标出口节点；优点是没有公网入口、抗通报能力强、单价更便宜；代价是要自备云前置，延迟比极致专线略高。

可以这样理解：IPLC 和 IEPL 像是"自带前导车的高速快车"，IX 更像是"先用地铁进城、再换专线出城"。后者的总开销更低，但控制力也部分转移到了云前置这一段。

需要警惕的是：不少宣传会把 IEPL、IPLC、IX 的稳定性按"高、中、低"排序，这种说法是不严谨的。三者互为补集，不是简单的优劣替代关系。

## 三、用 IX 互联专线之前，先核对云前置

选购之前最重要的一步，是确认自家已经在用的云主机能不能作为 IX 的前置。Mkcloud 的官方接入条件如下：

- 深圳入口：阿里云国内全网（通知群公告显示暂时受限，需等阿里云整改完成）、腾讯云、百度云国内全网、火山云华南、华为云华南；
- 上海入口：阿里云、腾讯云、百度云国内全网，火山云、华为云、UCloud 华东。

不支持"普通 BGP 主机代替"，也不支持"任意云主机或家用宽带"。如果还没有云前置，要先准备一台相应厂商、相应地域的云主机，并预留一定的内网带宽和按量计费预算。

前置机和 IX VPS 的费用要一起算。IX 便宜的入门款是几百元/月，但很多用户忽略了云前置的年付和流量费用，这部分也要纳入预算。

## 四、选 IX 套餐时真正应该看的几个维度

只看 Mbps 数字是不够的。建议优先核对以下几点：

1. 端内延迟：能反映出跨境段质量，但不能当作"业务真实全程 RTT"；
2. 带宽模式：是共享峰值还是独享速率，两者是不同指标；
3. 计费方式：流量计费还是带宽计费。流量套餐一般按上行、下行双向累计，超量后停机；
4. 入口云厂范围：是否覆盖你在用的云厂商、地域；
5. 出口资源：是否对接 PCCWG、HE、NTT、Cogent 等主要国际骨干，是否有 Google、Cloudflare 的 PNI；
6. IP 属性：明确是机房 IP，不承诺住宅或流媒体解锁属性。

另外要核对政策边界：IX 互通专线默认无 SLA 保证，仅质量问题支持退款，开通后不支持更换其他地域。

## 六、四条线路方向分别适合什么场景

深港 IX（深圳 → 香港）：端内延迟 1~2ms，香港 BGP 出口对接 PCCWG、RETN、NTT、Cogent、Lumen、Telstra、HE、Voxility 以及 Equinix IX、HKIX，并带有 Google、Cloudflare、Valve、SGGS 的私有 PNI。华南团队做电商后台、SHOPEE 店铺、移动端验证、低延迟香港 API 调用，深港方向是首选。

沪港 IX（上海 → 香港）：端内延迟 21ms，上海侧的云前置覆盖阿里、腾讯、百度、火山、华为、UCloud 华东。需要连到香港的 API、上传素材到香港存储、做跨境合规审计、登录香港 SaaS 后台，都可以走沪港方向。

沪日 IX（上海 → 日本）：端内延迟 25~28ms，日本侧 BGP 出口对接 PCCWG、NTT、Cogent、Lumen、Telstra、HE、Voxility，交换中心覆盖 Equinix IX、JPIX、BBIX、JPNAP。日区后台、亚马逊日本站、独立站测试、日本 SaaS 远程办公都是这条线的常见用途。

沪美 IX（上海 → 美国）：端内 124~134ms。跨境距离摆在那里，延迟不是强项，但 IX 互联的形式相比普通专线有助于减少跨境段被 DDoS 的概率。适合美区店铺运营、TikTok 美区账号环境、独立站 API 调用等对延迟容忍、对安全要求较高的任务。

## 七、IX 互联专线怎么连，六个动作就够了

Ix 类产品和传统直连产品的接入思路不同。传统直连绑定一个省份，从本地宽带或指定运营商网络即可连入；IX 则必须通过云厂商内网。

一个标准的接入流程是：

1. 核对云厂商、地域是否在 IX 的支持范围，确认已有云主机是否符合条件；
2. 在云厂商侧检查安全组、放通 IX VPS 入口 IP 的对应端口；
3. 从云主机控制台使用 SSH 或远程桌面登录 IX VPS 的入口地址；
4. 在 IX VPS 内部署目标业务（浏览器、脚本、API 客户端等）；
5. 在 IX VPS 内部验证出口 IP，确认业务流量确实从目标国家的出口发出；
6. 持续观察一周的业务延迟、丢包率、流量消耗，再决定是否升级或扩展。

有两点容易被忽略：其一，远程登录 IX VPS 之后，本地电脑的 IP 不会变化，IX 不会代理本地流量；其二，IX VPS 的出口 IP 不接受外部连接入，因此不能放到公网站点、回调地址或游戏服务端。

## 八、不能忽略的几条边界条件

IX 互联专线属于网络资源，不等于合规通行证，也不等于自带的高可用方案。具体使用时，建议先确认以下边界：

- 合规用途：Mkcloud 全部产品需中国身份实名，仅限个人或企业正规用途，禁止机场、回国等违法用途。2026 年阿里云合规整改期间，深圳 / 上海两地的阿里云至 IX 方向流量被临时切断，需等整改完成后才会恢复；
- SLA：默认无 SLA 保证。如需金融级可用性或书面 SLA，需走付费定制通道；
- 退款：仅质量问题支持退款，必须在工单中提交延迟、速度等具体测试数据；开通后不支持更换到其他地域；
- 资源稳定性：Mkcloud 在 2026 年发出过通知，因 IX 需求激增、产品多次临时售罄，说明 IX 类资源受上游云产能的影响较大，建议测试后再扩量；
- IP 与解锁：所有 IX VPS 出口为机房 IP，不承诺原生或住宅属性，不保证特定流媒体解锁；
- 维护通知频次：2026 年 4 月、5 月、6 月针对沪日、沪美、沪港 IXP 都发出过 15 至 60 分钟不等的维护通知，业务侧需要预留回退方案。

把这些边界写进 SLA 谈判，或者至少放在内部风险评估里，比事后补救要省心。

## 九、IX、IPLC、IEPL 三类方案怎么选

如果只用一句话总结：先看业务链条，再看预算。

- 已经大量使用云厂商（阿里云、腾讯云、火山、华为、UCloud 等），希望以较低的额外成本接入跨境专线，IX 是目前性价比最高的一档；
- 对跨境段延迟、稳定性的要求高于一切，且可以承担每年数千到数万的预算，可以直接走 IPLC 或 IEPL；
- 业务同时依赖本地办公网络、不方便自备云前置，IPLC / IEPL 更省事，因为服务商已经把本地入口和前置做好了；
- IX 与公网 VPS 不在同一安全模型，IX 不是用来承载公开站点或回调的，云前置也不能用普通 BGP 服务器代替。

把这四个判断对到 Mkcloud 的四方向上，配置思路就很清晰了：深港 IX 走华南和香港低延迟、沪港 IX 走上海对港通用任务、沪日 IX 走日区业务、沪美 IX 走美区耐延迟长链路任务。如果预算允许，把现有方案改成"云前置 + IX VPS + 云侧业务"三段式，比单买一台"传统跨境专线 VPS"要稳定得多。
